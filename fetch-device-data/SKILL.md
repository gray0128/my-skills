# 拉取设备数据

只用 HTTP POST 调接口。路径、请求体、响应字段和鉴权要求见 [references/api-map.md](references/api-map.md)。

核心原则：**除非当前步骤必须调用需要鉴权的 `/ddslp/` 接口，否则不要要求用户提供 token，也不要把 token 发送给无需鉴权的接口。**

## 1. 收齐前置条件

先收齐完成当前请求真正需要的信息，不要把 token 当成默认必填项：

| 项 | 完成标准 |
|----|----------|
| base URL | 形如 `http(s)://host[:port]`，无路径后缀 |
| 设备 | `deviceCode` |
| 时间范围 | 可换算的起止时间。时区默认 `Asia/Shanghai`，告知用户即可，不要再问 |
| 数据项 | 优先使用用户已给的 `pointId` / `kpiId`；若未给，见第 3 节 |
| token | **可选**。仅在必须调用 `/ddslp/` 且当前没有可用 token 时再索取 |

用户只给了环境别名、没给 host 时，要其给出完整 base URL。

如果用户已经给出 `pointId` 和 `kpiId`，不要为了“核对一下”而调用目录接口，更不要因此索取 token。

如果用户没有给 `pointId` / `kpiId`：

1. 优先请用户直接提供目标测点和 KPI 标识，这样可以继续走免 token 流程。
2. 只有用户不知道这些标识、确实需要 Agent 调目录查询时，才说明目录接口需要鉴权并索取 token。

完成标准：已有 base URL、deviceCode、时间范围，并且已知目标 `pointId` / `kpiId`；或者已确认需要通过目录接口查询目标数据项。token 不属于通用完成条件。

## 2. 如何调用

拼接：`{baseUrl 去尾斜杠}{path}`，`path` 以 `/` 开头。api-map 里同一 busout 能力可能有两条 path（`/api/busout/...` 与 `/iehm-cloud/api/v1/busout/...`）；先用表中默认，HTTP 404 再试另一条，仍失败则把两条 URL 和状态码告诉用户。

### 鉴权策略

按路由选择是否携带 token，不要“一律带 token”：

- `/api/busout/`：默认**不带 token**。
- `/iehm-cloud/api/v1/busout/`：默认**不带 token**。
- `/iehmBusOut/`：默认**不带 token**。
- `/ddslp/`：需要 token；请求头同时带 `token`、`x-token`，值均为用户 token。

即使用户此前提供过 token，调用前三类免 token 路由时也默认不要附带凭据，减少不必要的凭据暴露。

若免 token 路由返回**明确的鉴权失败**，再根据实际响应向用户索取 token 或说明该环境的鉴权策略与已验证环境不同；不要因为普通业务空结果、参数错误或后端 Java 异常就推断“需要 token”。

每次请求：

- `POST`，`Content-Type: application/json`
- body 按 api-map：有的是顶层字段，有的是 `{"params":{...}}`
- 仅 `/ddslp/` 或已明确验证需要鉴权的路由携带 `token` / `x-token`
- 不要在回复、日志摘要或错误信息里回显 token

### 并发控制

- **所有接口调用统一限制为最多 5 个并发请求**；任意时刻 in-flight 请求数不得超过 5。
- 批量拉多个设备、测点、KPI 或历史时间分片时，使用并发池/队列调度，不要一次性并发发出全部请求。
- 同一信号的原始数据分页依赖分页进度和终止条件，默认按页顺序拉取，不要为了提速突破全局并发上限。

### 响应与鉴权失败判定

不要用一套规则判断所有路由：

- `/ddslp/`：若 `__sys__.status == -1` 且消息包含「票据过期」「请求不合法」「重新登录」「合法权限」等鉴权提示，才按鉴权失败处理；没有 token 时向用户索取，有 token 时请用户更新 token。
- busout：优先看 HTTP 状态、`code`、`msg` 和预期 `data` 字段。HTTP 200、`code=200` 且业务字段正常即可视为调用成功。
- `/iehmBusOut/`：能进入业务层但返回诸如 Java 空对象、参数错误等消息，说明请求已穿透到后端，**不能据此判断需要 token**。
- 只有响应明确表明鉴权失败时才索取 token；其余情况按路径、参数、时间窗或数据是否存在来排查。

## 3. 确定数据项

目标是**尽量在不调用目录接口的情况下确定数据项**。

- 用户已给 `pointId` + `kpiId`：直接沿用，不调用目录。
- 用户明确说「原始信号」「波形」「信号」：按信号处理。
- 用户明确说「非信号」「历史时序」「历史原始数据」：按非信号处理。
- 已知 `pointId` + `kpiId`，但信号类型不明确：优先用免 token 接口探测，而不是查目录：
  1. 先按第 4 节调用非信号历史接口；若有 `data.timestamps`，按非信号处理。
  2. 若为空，再调用 busout 的信号采集时刻接口；若有信号时刻，按信号处理。
  3. 两边都为空时，不要据此武断判断类型；告诉用户当前窗口没有可用于判定的数据。若必须通过目录确认，再进入下面的目录流程。
- 用户未提供目标测点/KPI：优先请用户直接给 `pointId` / `kpiId`。如果用户不知道，需要 Agent 列目录时，此时才请求 token。

目录接口需要 token：

`POST /ddslp/service/LPDS01/getPointAndKpiListByDeviceCodeList`

body：

`{"params":{"deviceCodeList":["<deviceCode>"]}}`

目录返回后：

- 未指定、或只要「某一个」：列出候选，请用户选。
- 「全部信号 / 全部数据项」：按用户要求确定集合。
- 信号判定可使用 KPI 名含「波形」或目录字段 `isSignal`；仍吃不准时再问用户。

完成标准：每个目标有 `pointId`、`kpiId`，并能确定走信号或非信号流程；不要求仅为“核对”而调用目录。

## 4. 非信号

非信号历史原始数据优先使用免 token 的 busout 接口，不要因为缺 token 停止。

拉取「历史原始数据」时，**单次接口调用的时间范围最大不得超过 30 天**：

- 用户请求的时间范围 ≤ 30 天：一次调用历史原始数据接口，窗口用毫秒。
- 用户请求的时间范围 > 30 天：Agent 自行按连续时间窗口拆成多个 **≤ 30 天** 的分片，不要让用户手工拆分；按第 2 节的并发规则拉取，**总并发不得超过 5**。
- 所有分片完成后，按时间顺序拼接 `timestamps` 及其对应数据；对分片边界可能出现的同一 timestamp 做去重，保证时间序列有序且数据一一对应。
- 任一分片失败时，明确指出失败分片的起止时间和接口错误；不要把缺失分片静默当作完整结果。

`data.timestamps` 非空即为该分片完成。空结果本身不代表鉴权失败。若该 KPI 已知或探测后确认是波形 → 第 5 步。

完成标准：整个用户时间范围已覆盖并完成拼接；若存在失败分片，则明确标记结果不完整。

## 5. 信号

**默认拉取原始信号数据。** 用户未明确指定数据类型时，不要反问「原始还是降采样」；直接按原始流程执行，并告知用户：**也可以选择降采样数据**。

原始信号整条默认链路应优先使用免 token 接口：

`busout 采集时刻 → iehmBusOut 元数据 → iehmBusOut 原始分页`

不要为了拉原始信号而先索取 token。

1. **采集时刻（免 token 优先）**  
   默认调用 busout 的「时间范围内信号点」接口，不要先走 `/ddslp/` 的同能力接口。只要一个点时，取距目标时刻最近的 `timestamp`，并告诉用户该时刻。  
   完成标准：至少一条采集时刻。毫秒 `DTimeMs = timestampNs / 1e6`。

2. **原始（默认，免 token，三步不要跳）**  
   - 时刻：上一步已有。  
   - 元数据：用纳秒 `DTime` 调 `/iehmBusOut/` 的「信号详情」，拿到 `hz`、`cl`、`startTime`、`endTime`。缺任一字段则停止并展示必要的业务错误信息；不要因为业务异常改为索取 token。  
   - 分页：用 `startTime`/`endTime` 调 `/iehmBusOut/` 的「原始信号」。`offset=0`，`limit` 取 `min(cl, 50000)`。将每页 `times`/`values` 拼接；`offset += 本页条数`，直到累计条数 ≥ `cl`、或本页为空、或本页条数 < `limit`。  
   完成标准：写明累计点数与 `cl`（含少 1 点），并注明这是原始信号数据。

3. **降采样（可选，需要 token）**  
   只有用户明确要求服务端降采样波形时，才调用 `/ddslp/service/LPBI01/getSignalKpiValueListByCondition`。  
   - 如果此时没有 token，**到这一步再向用户索取**，不要提前索取。
   - 用 `DTimeMs` 调「信号波形」。
   - 交付时写明 `isOriginal` 与 `len(values)` / `cl`，并明确注明结果为降采样数据。

## 6. 什么时候才向用户要 token

只有以下场景默认需要 token：

1. 用户没有提供 `pointId` / `kpiId`，也不知道目标数据项，需要调用 `/ddslp/` 目录接口查询。
2. 用户明确要求服务端降采样波形，需要调用 `/ddslp/` 降采样接口。
3. 原本预计免 token 的路由在当前环境返回了**明确鉴权错误**，且没有其他免 token 路径可完成同一目标。

以下情况**不要**索取 token：

- 已知 `pointId` / `kpiId`，拉非信号历史原始数据。
- 已知 `pointId` / `kpiId`，拉原始信号。
- busout 返回空 timestamps。
- `/iehmBusOut/` 返回业务层参数错误、空对象或 Java 异常。
- 仅仅为了确认 KPI 名称、类型或“保险起见”。

## 7. 交付

每个数据项：base URL、设备、测点、kpi、时间窗、调用的 path、是否原始/降采样、点数、信号的 `cl`/`hz`。用户要求文件时再写 JSON。

不要输出 token，也不要说明 token 的具体值。必要时只说明某一步「使用了鉴权」或「未使用 token」。

若信号按默认流程返回原始数据，在交付中顺带告知用户：如只需要趋势查看或更小数据量，也可改取降采样数据；服务端降采样接口需要 token。
