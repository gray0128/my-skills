## Responsibility

让外部程序替 Agent 干活：把任务交给本机的编程 Agent CLI 并行执行，或借用用户已登录的浏览器读写外部平台内容。本主题的技能自己不产出判断，只操作别人提供的执行环境。

## 外部依赖是环境，不是仓库

本主题的技能都依赖仓库之外的东西：宿主机器上装了哪些 CLI、Chrome 里登录了哪个账号。这些是**运行环境**，不是仓库的依赖边——技能在缺依赖时按失败分类上报，不假装成功。`architecture` 的"脚本自成闭环"在这里意味着：脚本运行所需的一切（配置模板、忽略规则、测试）留在技能目录内，而外部工具本身由使用者准备。

## Skills

| 技能 | 驱动的对象 | 何时用 |
|---|---|---|
| `multi-agent-cli-dispatch` | 本机的 `claude`、`grok`、`reasonix`、`codebuddy`、`agy` | 同一任务交给多个 CLI 并行跑、监控完成情况，或对比不同 Agent 的输出 |
| `x-com-post` | 用户 Chrome 登录态下的 X.com | 读取推文/长文/线程内容，或发布、推广推文 |

## Invariants

**结果可回看.** 分发类工作落盘到 `runs/<timestamp>/`（含 `summary.md` 与各 Agent 日志）；判定以落盘内容为据，不以终端即时输出为据。署名比较按统一基准归一（大小写、全角/半角、分隔符），避免把同一答案的不同写法判成不一致。

**凭据不落明文，会话可持久化.** 不读取、不回显、不提交账号密码或 Cookie 明文。允许用会话状态文件（如 `agent-browser state save` 的产品）持久化登录态，这是唯一合法的持久化方式，但该文件内容不得出现在输出或提交物中。未登录时停下让用户自己登录，不尝试绕过。

**破坏性操作要独占.** 只读可以附着在正在使用的环境上；写入（发布内容、改动外部平台状态）要求独占该环境，两者在技能内部分成两条路径，不能混用。发帖类动作还需用户确认内容。

**不抽象平台.** 一个技能对接一个平台就照一个平台写，不为想象中的第二个平台预留通用层。真正的第二个平台出现时再决定是否合并。
